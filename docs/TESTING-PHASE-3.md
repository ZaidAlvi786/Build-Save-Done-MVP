# Phase 3 two-phone field protocol

Use two different physical phones, Android first (prefer different Android vendors; add iOS when a macOS build host is available). Use Expo development builds, not Expo Go. Apply migrations and deploy all five functions, including refresh-place. Credentials must be configured locally. Do not commit screenshot/location/token evidence.

1. Save real places on each phone and select Nearby reminders and debug. Read the permission explanation, set 300m, then Enable. On Android Settings choose Allow all the time. Capture notification/location status, native registered IDs/radii and expected selection count from the debug screen.
2. Deny foreground, background and notifications separately. Verify that the saved list and manual navigation remain usable and no reminder is recorded as sent for denied notifications. Grant access in Settings and explicitly retry Enable. Test approximate location and low-power mode separately.
3. Start outside a selected region, walk/drive safely into it with the app in the background and screen locked. Have a passenger operate the phone while driving. Record phone/OS, permission settings, battery mode, timestamps, expected place/radius, enter/exit debug entries and actual notification appearance. Repeat on both phones; mocked tests do not satisfy the gate.
4. Select Navigate; verify destination pin and exactly one reminders row/action=navigate with action_at. Repeat with Snooze and Already been on distinct reminders. Check that Already been sets visited and removes that region; Snooze blocks new entries for 24 hours. Replay the same notification response and verify the first action remains unchanged.
5. Turn off networking, enter a region and tap an action. Reopen after restoring networking; use Retry reminder sync. Verify the same reminder UUID/timestamps and one database row. Test termination between scheduling and local acknowledgement, and between server write and local acknowledgement.
6. Save more than 20 destinations. Check only the nearest 20 unvisited fresh coordinates register, and category filters do not narrow reminder coverage. Move over 1km, inspect selection changes, then foreground the app and check reconciliation. OS timing can delay changes; record it rather than assuming instant coverage.
7. Test different radii, visited/delete swipe and buttons, category/near sort, map failure, coordinate expiry/refresh, server timeout, app restart and Settings permission revocation. Expired regions must not notify. Confirm native selected regions match the debug state after changes.
8. Pause, sign out, switch accounts and delete an account. Verify tasks and displayed/scheduled reminders are removed, no old-account action can affect the new account, and local event/capture cleanup is correct. Offline actions survive sign-out only as account-bound rows; deletion removes them.
9. Force-stop/kill and test vendor battery restrictions. Reopen to recover; measure reliability and clearly document failures. On iOS verify cold notification action handling and the 20-region limit on hardware.

Pass requires a real reminder firing at the correct saved destination during a walk/drive on **both** phones, plus verified action logging and debug evidence. Record latency and all failed trials. Do not claim native compilation, OS wake reliability or notification delivery from prebuild/JS export alone.
